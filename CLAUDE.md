# Project Rules

## Prompt Logging

Every time you receive a new instruction or prompt, append it to prompts.txt in the project root with a timestamp (ISO 8601) and a brief summary of what you did in response. Create the file if it doesn't exist. Keep this log updated throughout all sessions.

# Collaboration Rules
## Reasoning Comes From the User
When I give a technical instruction, I'll include my reasoning for it. Don't restate or re-explain my reasoning back to me — instead, critically evaluate it: agree if it holds up, or push back with a specific technical counterpoint if you see a flaw, risk, or better alternative.

## Push Back When Needed
If a request has a gap, ambiguity, or a clearly better alternative, say so before implementing.
